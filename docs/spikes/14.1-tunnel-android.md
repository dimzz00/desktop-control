# Spike 14.1 — Tunnel TCP di client Android

## Pertanyaan

Apakah aplikasi RustDesk Android dapat membuka port lokal dari TCP tunneling sehingga
browser di Android dapat mengakses layanan di host (mis. terminal kendali)?

## Hasil riset (tanpa uji device)

- RustDesk mendukung `enable-tunnel` di client (termasuk mobile); dokumentasi resmi:
  Settings → Security → Permissions → Enable TCP tunneling.
- `src/port_forward.rs` (RustDesk) menunjukkan listener dibuka di `127.0.0.1:<port>`
  pada sisi *pengontrol* (client), lalu meneruskan ke `remote_host:remote_port` di host.
- CLI: `rustdesk --port-forward <ID> <local_port> <remote_host> <remote_port>`.
- Implikasi: browser Android seharusnya dapat mengakses `http://127.0.0.1:<port>` selama
  aplikasi RustDesk berjalan dan tunnel aktif.

## Prosedur verifikasi (perangkat nyata)

1. Pasang RustDesk Android (versi yang dikunci di `deps.lock`).
2. Aktifkan `enable-tunnel` di host (Settings → Security → Permissions).
3. Dari Android, hubungkan ke host, buka TCP tunnel: local port 47654 → 127.0.0.1:47654.
4. Buka browser Android, akses `http://127.0.0.1:47654`.
5. Catat: apakah halaman termuat, apakah tunnel tetap hidup saat app di background.

## Hasil uji (laporan pengguna)

Pengguna tidak menemukan menu TCP tunnel di aplikasi RustDesk Android. Dokumentasi resmi
hanya menyebut `enable-tunnel` sebagai izin di sisi yang dikontrol (host), bukan sebagai
fitur pembuka tunnel di sisi pengontrol pada Android. Fitur TCP tunnel (port_forward)
terdokumentasi dan diuji pada client desktop (Windows/Linux/macOS), bukan Android.

## Keputusan

- [x] **Tidak tersedia di client Android** → terminal 0.2.0 memakai `bind: tailnet` bertoken
  (fallback utama sesuai §14.1).
- [ ] Terminal pindah ke transport sendiri di atas tailnet (cadangan jika tailnet tidak memadai).

## Catatan

Spike ini tidak bisa diverifikasi di lingkungan pengembangan (tanpa device Android).
Hasil uji perangkat harus dicatat di sini sebelum merencanakan 0.2.0.
